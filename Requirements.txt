USER ROLES

There are two roles:

SUPER ADMIN
- Full access to the administration panel
- Can access all modules
- Can create users
- Can edit users
- Can disable users
- Can assign Admin or Super Admin roles
- Can manage other administrative users

ADMIN
- Can access the administration panel
- Can access all normal convention-management functionality
- Cannot create users
- Cannot manage users
- Cannot change user roles

Keep the authorization architecture simple and extensible.

Use role-based authorization rather than hard-coding checks throughout individual pages.

For example, create reusable authorization functions/middleware such as:

requireLogin();
requireRole('super_admin');

Do not duplicate authentication logic inside every page.

AUTHENTICATION

Implement:

- Login page
- Logout
- Secure PHP sessions
- Password hashing using password_hash()
- Password verification using password_verify()
- Session regeneration after successful login
- Authentication middleware
- Authorization middleware
- Protection against unauthenticated access to dashboard pages
- Protection against Admin users accessing Super Admin-only functionality
- CSRF protection for POST forms
- Server-side validation
- Prepared SQL statements
- No plaintext passwords

Do not store passwords in plaintext.

- name
- email
- password_hash
- role
- is_active
- created_at
- updated_at
- last_login_at

Use an appropriate database design and indexes.

Use environment variables/configuration for database credentials.

- authentication

SECURITY

Treat security as a first-class requirement.

Implement the foundation with:

- Prepared SQL statements
- Password hashing
- CSRF protection
- Session security
- Authentication middleware
- Authorization middleware
- Input validation
- Output escaping
- Secure error handling
- No credentials in source control

Do not expose database errors, passwords, stack traces, or internal paths to users.

Use htmlspecialchars() or an appropriate escaping helper when rendering user-controlled text.

CODE QUALITY

Use clear PHP naming conventions.

Avoid giant PHP files.

Avoid duplicating HTML.

Avoid mixing large amounts of database logic directly into presentation files.

Keep authentication, authorization, database access, components, and page logic separated.

Use comments only where they add useful context.

Do not add unnecessary dependencies.
